wp-bulk — Формат вызова команд

Единая точка входа для всех команд WordPress Bulk Editor

Общий формат:

Все команды вызываются через единый CLI:

wp-bulk [ГЛОБАЛЬНЫЕ ОПЦИИ] КОМАНДА [ПАРАМЕТРЫ КОМАНДЫ]
Глобальные опции:
--project, -P имя проекта из папки projects/
Важно: Глобальные опции (--project) указываются ДО имени команды, а параметры команды — ПОСЛЕ.
Примеры вызова:
wp-bulk sync --file example.xlsx
Без проекта — используется глобальный .env из корня репозитория
wp-bulk -P mysite sync --file example.xlsx
С проектом — используется projects/mysite/.env и пути проекта
wp-bulk --project ost fetch
Полная форма флага --project
Доступные команды:
Синхронизация:
  • sync
  • async
Получение данных:
  • fetch
  • fetch-media
  • export
  • export-media
Google Sheets:
  • download-google-sheet
  • upload-to-google-sheets
  • sync-from-google
  • sync-google-bidirectional
  • async-from-google
  • async-google-bidirectional
Утилиты:
  • validate
  • options
  • bulk-delete
  • counter
  • llm
  • reshape
  • vlook

Работа с проектами (--project / -P)

Управление несколькими WordPress сайтами из одной установки

Назначение: Система проектов позволяет работать с несколькими WordPress сайтами, храня конфигурацию, данные и логи каждого сайта в изолированной папке projects/<name>/.
Структура папки проекта:
projects/ ├── mysite/ # Проект "mysite" │ ├── .env # Credentials и настройки этого сайта │ ├── mysite.xlsx # Excel файл (авто-обнаружение) │ ├── media/ # Медиафайлы проекта │ ├── content/ # Экспортированный контент │ └── logs/ # Логи операций ├── blog/ # Проект "blog" │ ├── .env │ ├── data.xlsx │ ├── media/ │ ├── content/ │ └── logs/ └── ...
Создание нового проекта:
mkdir projects/mysite
1. Создайте папку проекта
cp .env.example projects/mysite/.env
2. Скопируйте шаблон .env и заполните credentials
Три способа указать проект:
Способ Пример Описание
Флаг -P wp-bulk -P mysite sync Короткая форма (рекомендуется)
Флаг --project wp-bulk --project mysite sync Полная форма
Переменная окружения set WP_PROJECT=mysite Через переменную окружения WP_PROJECT
Что меняется при работе с проектом:
Ресурс Без проекта С проектом (-P mysite)
.env файл .env (корень) projects/mysite/.env
Excel файл Указывается через --file Авто-обнаружение в projects/mysite/
Логи logs/ projects/mysite/logs/
Медиа data/media/ projects/mysite/media/
Контент data/content/ projects/mysite/content/
Export output Указывается через --output projects/mysite/exported_content/
Авто-обнаружение Excel файла (только для fetch):
  • Команда fetch без --file автоматически ищет .xlsx в папке проекта
  • Если в папке один .xlsx файл — он используется автоматически
  • Если файлов несколько — приоритет у файла с именем проекта (например mysite.xlsx)
  • Если файл не найден — создается fetch.xlsx в папке проекта
Важно: Команды sync, async, validate, fetch-media, llm всегда требуют параметр --file. Проект влияет на расположение .env, логов, медиа и output — но не подставляет файл автоматически для этих команд.
Примеры работы с проектами:
Выгрузка данных (fetch автоматически найдет/создаст файл):
wp-bulk -P ost fetch
Авто-режим: создаст projects/ost/fetch.xlsx с данными сайта
wp-bulk -P ost fetch --sheets posts,pages --status publish
Выгрузить только опубликованные посты и страницы
Синхронизация (--file обязателен):
wp-bulk -P ost sync --file projects/ost/fetch.xlsx
Синхронизация: .env из проекта, логи в projects/ost/logs/
wp-bulk -P ost async --file projects/ost/ost.xlsx --sheets posts --concurrency 10
Async синхронизация постов проекта "ost"
Экспорт (output авто-направляется в папку проекта):
wp-bulk -P ost export
Экспорт в projects/ost/exported_content/ (авто-определение output)
wp-bulk -P ost export-media
Экспорт медиа в projects/ost/export_media/
Утилиты:
wp-bulk -P ost llm --file projects/ost/ost.xlsx --column excerpt
LLM генерация: LLM_ENDPOINT, LLM_TOKEN берутся из projects/ost/.env
wp-bulk -P tzm bulk-delete --post-type posts --status draft --dry-run
Показать черновики постов проекта "tzm" (--file не нужен)
wp-bulk -P ost counter --type posts --output stats.csv
Подсчет слов: CSV сохранится в projects/ost/counter_output.csv
Пример .env файла проекта: 
# projects/mysite/.env
WP_URL=https://mysite.com
WP_USERNAME=admin
WP_PASSWORD=xxxx xxxx xxxx xxxx

# Google Sheets (опционально)
GOOGLE_SHEET_ID=1B5gj1nxzVhQ...
GOOGLE_SHEET_CREDENTIALS_PATH=credentials/google.json

# LLM (опционально)
LLM_ENDPOINT=http://localhost:8317/v1/chat/completions
LLM_TOKEN=your-api-key
LLM_MODELS=gpt-4,claude-3
LLM_PROMPT=Напиши текст для [title]
Приоритет настроек:
  1. Параметры командной строки (--domain, --file, --env-file) — наивысший приоритет
  2. .env файл проекта (projects/<name>/.env)
  3. Глобальный .env файл (корень репозитория)

Рабочие процессы

Обновление контента (Excel → WordPress)

Как массово создавать, обновлять и удалять записи WordPress из Excel

Принцип работы: Действие для каждой строки определяется колонкой action в Excel. Поддерживаются листы типов контента (posts, pages, кастомные), таксономий (categories, tags) и медиафайлов (media).
Поддерживаемые значения action:
action Описание Обязательные поля
add Создать новую запись в WordPress title (id будет заполнен автоматически)
update Обновить существующую запись id
delete Удалить запись из WordPress id
skip Пропустить строку (ничего не делать) —
Пошаговый процесс:
Шаг 1. Выгрузите данные из WordPress (или создайте Excel файл вручную):
wp-bulk fetch
Создаст fetch.xlsx со всеми записями сайта (action=skip у всех строк)
Шаг 2. Отредактируйте Excel файл:
  • Установите action=update для строк, которые нужно обновить
  • Добавьте новые строки с action=add для создания
  • Установите action=delete для удаления
  • Оставьте action=skip для строк без изменений
Шаг 3. Запустите синхронизацию:
wp-bulk sync --file fetch.xlsx
Синхронный режим. Для больших объемов используйте async
wp-bulk async --file fetch.xlsx --concurrency 10
Асинхронный режим: быстрее, с retry и circuit breaker
Что произойдет после синхронизации:
  • Новым записям (action=add) будет присвоен id и записан обратно в Excel
  • Action изменится на skip чтобы при повторном запуске не дублировать
  • Обновленные записи получат актуальные метаданные (link, slug и т.д.)
  • Удаленные записи будут помечены как обработанные
  • Логи сохранятся в папке logs/
С использованием проекта:
wp-bulk -P ost fetch
1. Выгрузить данные сайта "ost" → projects/ost/fetch.xlsx
wp-bulk -P ost async --file projects/ost/fetch.xlsx --sheets posts
2. Синхронизировать только посты проекта "ost"
Безопасность:
  • Используйте --dry-run для предварительной проверки (никакие изменения не применятся)
  • Используйте --test-mode --sheets posts для обработки только первых 3 строк
  • Используйте --skip-media и --skip-tax для ускорения, если нужно обновить только текст

Выгрузка контента (WordPress → файлы)

Как получить данные из WordPress в Excel или файлы

Две стратегии выгрузки:
  • fetch — в Excel файл (для дальнейшего редактирования и синхронизации обратно)
  • export — в HTML файлы + CSV индекс (для архивации или миграции)
Стратегия 1: fetch (WordPress → Excel)
Auto Mode (без --file): автоматически обнаруживает все типы записей и таксономий, создает новый файл с оптимальной структурой полей.
wp-bulk fetch
Создать fetch.xlsx со ВСЕМИ данными сайта
wp-bulk fetch --sheets posts,pages --status publish --limit 100
Только опубликованные посты и страницы, максимум 100
wp-bulk fetch --exclude post_tag,nav_menu
Все кроме тегов и меню навигации
Manual Mode (с --file): использует структуру существующего Excel файла — удобно для повторных выгрузок.
wp-bulk fetch --file data.xlsx --sheets posts,pages
Обновить данные в существующем файле
Стратегия 2: export (WordPress → HTML файлы)
wp-bulk export --output "backup/mysite"
HTML файлы + index.csv (группировка по типам: posts/, pages/)
wp-bulk export-media --output "backup/media" --concurrency 20
Скачать все медиафайлы с параллельной загрузкой
Что выгружается в fetch (автоматический режим):
  • Типы записей: posts, pages и все кастомные типы (кроме служебных)
  • Обязательные поля: id, date, modified, title, type, slug, link, parent, status
  • Дополнительные поля: content, excerpt, featured_media, image_url
  • SEO поля: seo_title, seo_description, seo_meta_keywords (если SEO плагин установлен)
  • ACF поля: все зарегистрированные ACF поля с префиксом acf_ (если плагин установлен)
  • Таксономии: categories, tags, кастомные таксономии
  • Action: у всех записей устанавливается "skip"
С использованием проекта:
wp-bulk -P ost fetch
Авто-режим: создаст projects/ost/fetch.xlsx
wp-bulk -P ost export
HTML экспорт в projects/ost/exported_content/
wp-bulk -P ost export-media
Медиа экспорт в projects/ost/export_media/

Работа с медиафайлами

Загрузка, редактирование, удаление и экспорт медиафайлов WordPress

Медиа в WordPress Bulk Editor: Управление медиафайлами происходит через лист media в Excel. Это отдельный тип листа, который поддерживает загрузку, обновление метаданных и удаление файлов из библиотеки WordPress.
Команды для работы с медиа:
Команда Направление Описание
fetch-media WordPress → Excel Выгрузить список медиафайлов в лист media
sync --sheets media Excel → WordPress Загрузить/обновить/удалить медиафайлы (синхронный)
async --sheets media Excel → WordPress То же, но параллельно с retry (рекомендуется)
export-media WordPress → файлы Скачать все медиафайлы на диск + CSV индекс
Структура листа media:
Колонка Описание add update delete
action Действие add update delete
id ID медиафайла в WordPress пусто (заполнится) обязательно обязательно
img_path Путь к файлу или URL обязательно — —
title Название опционально редактируемое —
alt_text Альтернативный текст (SEO) опционально редактируемое —
caption Подпись опционально редактируемое —
description Описание опционально редактируемое —
Полный процесс работы с медиа:
1. Получить список текущих медиафайлов:
wp-bulk fetch-media --file data.xlsx
Создаст лист media со всеми файлами библиотеки (action=skip)
2. Отредактировать Excel:
  • Добавить строки с action=add и img_path для загрузки новых файлов
  • Установить action=update и изменить alt_text, title и т.д. для массового SEO обновления
  • Установить action=delete для удаления ненужных файлов
3. Синхронизировать:
wp-bulk async --file data.xlsx --sheets media --concurrency 3
Параллельная обработка (3 файла одновременно) с retry
wp-bulk sync --file data.xlsx --sheets media
Синхронный режим (последовательная обработка)
Загрузка файлов (action=add):
Поддерживаемые источники для img_path:
  • Локальный файл: images/photo.jpg — ищется от текущей папки или из data/media/ (или projects/<name>/media/ при использовании проекта)
  • URL: https://example.com/image.png — файл скачивается и загружается
  • Поддерживаемые форматы: изображения (jpg, png, gif, webp), видео, документы
После загрузки (action=add) автоматически заполнятся:
  • id — присвоенный WordPress ID
  • link, source_url — URL файла на сайте
  • mime_type — тип файла
  • action → изменится на skip
Featured image (обложка записи):
Привязка медиа к записям:

Чтобы установить обложку записи, используйте колонку featured_media в листе контента (posts, pages):

  • Укажите featured_media = ID медиафайла (числовой ID из WordPress)
  • Или используйте image_url = URL изображения — файл будет загружен и привязан автоматически
  • Флаг --delete-media удалит обложку при action=delete записи
  • Флаг --skip-existing-media ускоряет массовое обновление, не перезаписывая существующие обложки
Экспорт медиа (скачивание файлов):
wp-bulk export-media --output "backup/media" --concurrency 20
Скачать все файлы + media_index.csv с метаданными
wp-bulk export-media --no-download-files
Только CSV индекс без скачивания файлов
Удаление медиа (action=delete):
  • Удаление необратимо — файл полностью удаляется из WordPress (не в корзину)
  • Если файл используется в записях — останутся битые ссылки
  • Рекомендуется сначала проверить через --dry-run

Справочник команд

sync

Синхронизация данных из Excel файла в WordPress

Назначение: Основная команда для массового создания, обновления и удаления контента WordPress из Excel файла.
Параметры:
--file путь к Excel файлу --sheets список листов через запятую --dry-run режим симуляции (без изменений) --verbose подробные логи --concurrency параллельные запросы (default: 5) --skip-media пропустить загрузку медиа --skip-tax пропустить обновление таксономий (категории, теги) --skip-existing-media не прикреплять существующие featured_media при update (ускоряет массовое редактирование) --delete-media удалять featured media при action=delete --no-update-excel не записывать ID обратно в Excel --test-mode обработать только первые 3 строки (требует --sheets с одним листом) --columns колонки для обновления через запятую (excerpt,seo_title). Остальные поля не отправляются --domain URL WordPress сайта --username имя пользователя --password Application Password --env-file путь к кастомному .env файлу
Примеры использования:
wp-bulk sync --file example.xlsx
Полная синхронизация всех листов
wp-bulk sync --file w.xlsx --sheets posts --columns excerpt,seo_title
Обновить только excerpt и seo_title для листа posts
wp-bulk sync --file w.xlsx --sheets posts,pages
Синхронизация только определенных листов
wp-bulk sync --file data.xlsx --sheets posts --dry-run --verbose
Тестовый режим с подробными логами
wp-bulk sync --file w.xlsx --domain https://example.com --username admin --password "xxxx xxxx xxxx xxxx"
С явным указанием credentials
wp-bulk sync --file data.xlsx --skip-tax
Обновить только поля контента, пропустив таксономии (ускоряет синхронизацию)
wp-bulk sync --file data.xlsx --skip-media --skip-tax
Обновить только основные поля, без медиа и таксономий (максимальная скорость)
С использованием проекта:
wp-bulk -P ost sync --file projects/ost/data.xlsx
Проект "ost": .env из projects/ost/.env, логи в projects/ost/logs/, медиа из projects/ost/media/
wp-bulk -P ost sync --file projects/ost/data.xlsx --sheets posts --dry-run
Тестовый режим для проекта "ost", только лист posts
Работа с листом 'media' (библиотека медиафайлов):

Команда sync полностью поддерживает управление медиафайлами через лист 'media' в Excel.

📁 Структура листа media:
  • action - действие (add, update, delete, skip)
  • id - ID медиафайла в WordPress (для update/delete)
  • img_path - путь к файлу для загрузки (для add)
  • title - название медиафайла
  • alt_text - альтернативный текст (для SEO и доступности)
  • caption - подпись
  • description - описание
Загрузка новых файлов (action=add):
  • Укажите img_path - путь к локальному файлу или URL
  • Локальные файлы ищутся от текущей папки или в data/media/
  • Поддерживаются изображения, видео, документы
  • После загрузки автоматически заполнятся: id, link, source_url, mime_type
  • Action изменится на "skip" чтобы избежать повторной загрузки
wp-bulk sync --file data.xlsx --sheets media
Синхронизация только медиафайлов
Редактирование медиа (action=update):
  • Требуется id существующего медиафайла
  • Можно изменить: title, alt_text, caption, description
  • Сам файл НЕ заменяется (только метаданные)
  • Полезно для массового обновления alt_text для SEO
Удаление медиа (action=delete):
  • Требуется id существующего медиафайла
  • Удаляется полностью из WordPress (не в корзину)
  • ВНИМАНИЕ: Необратимая операция!
  • Если файл используется в постах, там останутся битые ссылки
Примеры работы с media:
action id img_path title alt_text Результат
add пусто images/photo.jpg Фото продукта Описание для alt ✅ Загрузит файл, заполнит id
add пусто https://example.com/image.png Логотип ✅ Загрузит по URL
update 1234 пусто Новое название Обновленный alt ✅ Обновит метаданные
delete 1234 пусто 🗑️ Удалит файл полностью
skip 1234 Текущее название ⏭️ Пропустит, ничего не делает
Команды для работы с media: 
# Синхронизация (загрузка, редактирование, удаление)
wp-bulk sync --file data.xlsx --sheets media
wp-bulk async --file data.xlsx --sheets media

# Выгрузка списка медиа из WordPress
wp-bulk fetch-media --file export.xlsx
Формат вывода:
  • Прогресс синхронизации в реальном времени
  • Логи операций (создание, обновление, удаление)
  • Статистика: успешные/ошибки по каждому листу
  • Обновленный Excel файл с заполненными ID и метаданными

fetch

Получение данных из WordPress в Excel файл

Назначение: Выгрузка контента из WordPress в Excel для редактирования или анализа. Поддерживает два режима: ручной (с указанием файла) и автоматический (создание файла с нуля).
Режимы работы:
🤖 Auto Mode (Автоматический): Если параметр --file не указан, команда автоматически создаст fetch.xlsx и выгрузит все доступные типы записей и таксономий с сайта. Структура полей определяется автоматически на основе реальных данных.
📝 Manual Mode (Ручной): Если параметр --file указан, команда использует структуру существующего Excel файла для определения какие листы и поля выгружать.
Параметры:
--file путь к Excel файлу (если не указан, создается fetch.xlsx) --sheets список листов для выгрузки (posts,pages,category) --exclude список типов для исключения (posts,category) --status фильтр по статусу (publish/draft/any) --limit максимум записей на лист --domain URL WordPress сайта --username имя пользователя --password Application Password --env-file путь к кастомному .env файлу
Примеры использования:
🚀 Автоматический режим (рекомендуется для начала работы):
wp-bulk fetch --domain https://example.com --username admin --password "xxxx xxxx xxxx"
Создать fetch.xlsx с ВСЕМИ типами записей и таксономиями с сайта
wp-bulk fetch --sheets posts,category
Создать fetch.xlsx только с постами и категориями
wp-bulk fetch --status publish --limit 100
Только опубликованные записи, максимум 100 на лист
wp-bulk fetch --exclude post_tag,nav_menu
Выгрузить все типы кроме тегов и меню навигации
🔧 Фильтрация с помощью --exclude:

Параметр --exclude позволяет исключить определенные типы записей или таксономии из выгрузки.

  • Работает в обоих режимах: auto-mode и manual mode
  • Формат: список через запятую без пробелов
  • Применяется после: --sheets (если указан)

Полезно для:

  • Исключения служебных типов (nav_menu, post_format)
  • Пропуска больших таблиц (например, теги если их много)
  • Быстрой выгрузки без ненужных данных
wp-bulk fetch --exclude category,post_tag
Выгрузить все типы записей без таксономий
wp-bulk fetch --sheets posts,pages,category --exclude category
Комбинация: выбрать posts,pages,category, но исключить category (результат: posts,pages)
С использованием проекта (fetch поддерживает авто-обнаружение файла):
wp-bulk -P ost fetch
Авто-режим: создаст projects/ost/fetch.xlsx со ВСЕМИ типами записей. Credentials из projects/ost/.env
wp-bulk -P ost fetch --sheets posts,pages --status publish
Только опубликованные посты и страницы, файл — в projects/ost/
wp-bulk -P ost fetch --file projects/ost/custom.xlsx
Ручной режим: выгрузить данные в конкретный файл проекта
📝 Ручной режим (использование существующего файла):
wp-bulk fetch --file example.xlsx --status publish
Выгрузить данные в существующий файл, только опубликованные
wp-bulk fetch --file example.xlsx --sheets posts,pages
Выгрузить только листы posts и pages
Что выгружается:
  • Типы записей: posts, pages, и все кастомные типы (кроме служебных)
  • Обязательные поля: id, date, modified, title, type, slug, link, parent, status
  • Дополнительные поля: content, excerpt, featured_media, image_url (если есть)
  • SEO поля: seo_title, seo_description, seo_meta_keywords, и т.д. (если плагин установлен)
  • Таксономии: categories, tags, и все кастомные таксономии (если связаны с типом)
  • ACF поля: все зарегистрированные ACF поля с префиксом acf_ (если плагин установлен)
  • Action: для всех записей устанавливается "skip" (не будет синхронизироваться обратно)
Важно:
  • В auto-mode структура полей определяется анализом ВСЕХ записей - это гарантирует, что не пропустятся поля, которые заполнены только в некоторых записях
  • Особенно важно для ACF полей и кастомных таксономий, которые могут быть заполнены выборочно
  • Для таксономий обязательные поля: id, name, slug, link (остальные добавляются если присутствуют)
  • Порядок применения фильтров: 1) Discovery (обнаружение всех типов) → 2) --sheets (если указан) → 3) --exclude (если указан) → 4) Выгрузка
  • Нормализация имен: category → categories, post_tag → tags (для совместимости с WordPress REST API)

async

🚀 Асинхронная синхронизация Excel → WordPress (быстрее и надежнее)

Назначение: Продвинутая версия команды sync с параллельной обработкой строк, retry механизмом и circuit breaker для устойчивости.
Преимущества:
  • Параллельная обработка строк через Semaphore (не батчами)
  • Retry с exponential backoff - автоматический повтор при ошибках (5xx, timeout, network)
  • Circuit breaker - защита от перегрузки сервера (блокирует запросы после N ошибок)
  • Отдельные таймауты для API (30s) и медиа (120s)
  • Тестовый режим --test-mode для отладки (первые 3 строки)
Параметры:
--file путь к Excel файлу --sheets список листов через запятую --domain URL WordPress сайта --username имя пользователя --password Application Password --env-file путь к кастомному .env файлу --dry-run режим симуляции --verbose подробные логи --concurrency параллельные запросы (default: 5) --api-timeout API таймаут в секундах (default: 30) --max-retries максимум повторов (default: 3) --circuit-breaker / --no-circuit-breaker включить circuit breaker (default: on) --skip-media пропустить загрузку медиа --skip-tax пропустить обновление таксономий (категории, теги) --delete-media удалять featured media при action=delete --no-update-excel не записывать ID обратно в Excel --test-mode обработать только первые 3 строки --columns колонки для обновления через запятую (excerpt,seo_title). Остальные поля не отправляются
Примеры использования:
wp-bulk async --file example.xlsx
Полная асинхронная синхронизация всех листов
wp-bulk async --file w.xlsx --sheets posts --concurrency 10
Увеличенная concurrency для быстрых серверов
wp-bulk async --file data.xlsx --test-mode --verbose
Тестовый режим: обработать первые 3 строки с логами
wp-bulk async --file w.xlsx --max-retries 5 --api-timeout 60
Увеличить retry и timeout для медленного сервера
wp-bulk async --file data.xlsx --skip-tax
Обновить только поля контента, пропустив таксономии (ускоряет синхронизацию)
wp-bulk async --file data.xlsx --skip-media --skip-tax
Максимальная скорость: обновление только основных полей
С использованием проекта:
wp-bulk -P ost async --file projects/ost/data.xlsx
Проект "ost": .env, логи и пути медиа из projects/ost/
wp-bulk -P tzm async --file projects/tzm/tzm.xlsx --sheets posts --concurrency 10 --verbose
Проект "tzm": синхронизация постов с 10 параллельными запросами
Работа с листом 'media' (асинхронная):

Команда async полностью поддерживает управление медиафайлами через лист 'media'. Все операции (add, update, delete) выполняются параллельно с retry механизмом.

wp-bulk async --file data.xlsx --sheets media
Асинхронная синхронизация медиафайлов (загрузка, редактирование, удаление)
wp-bulk async --file data.xlsx --sheets media --concurrency 3
Параллельная загрузка 3 файлов одновременно
Преимущества async для медиа:
  • Параллельная загрузка: Несколько файлов загружаются одновременно
  • Retry при ошибках: Автоматический повтор если загрузка упала
  • Увеличенный timeout: 120 секунд для больших файлов
  • Circuit breaker: Защита от перегрузки сервера
📝 Структура и операции:

Лист 'media' поддерживает все те же операции что и в sync команде:

  • action=add - загрузить новый файл (требует img_path)
  • action=update - обновить метаданные (требует id)
  • action=delete - удалить файл (требует id)
  • action=skip - пропустить строку

Подробнее см. раздел "Работа с листом 'media'" в команде sync.

Настройка .env: Асинхронные команды используют параметры с префиксом WP_*: 
WP_SYNC_CONCURRENCY=5                # Параллельные запросы
WP_API_TIMEOUT=30                    # API таймаут (секунды)
WP_MEDIA_TIMEOUT=120                 # Медиа таймаут (секунды)
WP_MAX_RETRIES=3                     # Максимум retry
WP_RETRY_DELAY=1                     # Начальная задержка (exponential backoff)
WP_CIRCUIT_BREAKER_THRESHOLD=10      # Порог ошибок для circuit breaker
WP_CIRCUIT_BREAKER_RECOVERY=60       # Время восстановления (секунды)

llm

🤖 Массовая генерация контента через LLM API (OpenAI-compatible)

Назначение: Автоматическая генерация контента в указанную колонку Excel с использованием LLM моделей (GPT, Claude, Grok и т.д.). Обрабатывает только строки где action=update.
Возможности:
  • Подстановка значений: Используйте [column_name] в промпте для подстановки данных из других колонок
  • Fallback между моделями: Указывайте несколько моделей через запятую для автоматического переключения
  • Retry механизм: 3 попытки для каждой модели с exponential backoff
  • Пост-обработка: Конвертация Markdown ↔ HTML, удаление тегов
  • Streaming: Обработка streaming ответов от API
Параметры:
--column колонка для записи результата --model модели через запятую (или LLM_MODELS из .env) --file путь к Excel файлу (default: export.xlsx) --sheets листы для обработки --prompt промпт (или LLM_PROMPT из .env) --endpoint LLM API URL (или LLM_ENDPOINT из .env) --token API токен (или LLM_TOKEN из .env) --overwrite перезаписывать существующие значения --dry-run тестовый режим без сохранения --strip-tags удалить HTML теги --md-to-html конвертировать Markdown в HTML --html-to-md конвертировать HTML в Markdown
Настройка .env: 
LLM_ENDPOINT=http://localhost:8317/v1/chat/completions
LLM_TOKEN=your-api-key-here
LLM_MODELS=gemini-2.5-flash-lite,gpt-4,claude-3
LLM_PROMPT=Напиши текст для [title]
LLM_MODELS: Модели с fallback (через запятую). Если не указано, параметр --model становится обязательным.
Примеры использования:
wp-bulk llm --column excerpt
Использует LLM_MODELS, LLM_PROMPT из .env (самый быстрый способ)
wp-bulk llm --column excerpt --model "gpt-4" --prompt "Напиши короткий lead абзац к услуге [title]"
Генерация excerpt на основе title с явным указанием модели
wp-bulk llm --column description --model "grok-4.1-fast,gpt-4,claude-3" --prompt "Опиши услугу [title]: [excerpt]"
Fallback между моделями (если grok не ответит, попробует gpt-4, потом claude-3)
wp-bulk llm --column content --model "gpt-4" --prompt "Напиши подробную статью про [title]" --md-to-html
Генерация с конвертацией Markdown в HTML
wp-bulk llm --column excerpt --model "gpt-4" --sheets posts,pages --overwrite
Обработка конкретных листов с перезаписью существующих значений
wp-bulk llm --column description --model "gpt-4" --dry-run --verbose
Тестовый режим с подробными логами
Подстановка значений:

В промпте можно использовать любые колонки из Excel через [column_name]:

  • [title] - заголовок записи
  • [excerpt] - краткое описание
  • [categories] - категории
  • [content] - основной контент
  • И любые другие колонки из вашего Excel
Примеры промптов для SEO и контента:

Правильно составленные промпты помогут получить чистый результат без лишних оберток:

Meta Description (120-155 символов):
Напиши мета-описание 120-155 символов для услуги "[title]". Только текст описания, без кавычек и вступлений.
Meta Keywords (через запятую):
Напиши 5-7 ключевых слов для "[title]". Только список через запятую, без номеров и пояснений.
SEO Title (50-60 символов):
Напиши SEO заголовок 50-60 символов для "[title]". Только текст заголовка, без кавычек.
Lead абзац (1-2 предложения):
Напиши лид абзац 1-2 предложения для услуги: [title]. Только текст, без слов "Вот ответ" и подобных вступлений.
Описание товара (2-3 абзаца):
Напиши описание товара "[title]" из категории [categories]. 2-3 абзаца, простой текст без HTML и markdown.
Совет: Добавляйте фразы "Только текст", "Без кавычек", "Без вступлений" - это помогает получить чистый результат без оберток типа "Вот ответ:", кавычек или HTML тегов.
Обработка ошибок:
  • Если все модели не смогли сгенерировать текст, в ячейку записывается "error"
  • Полный текст ошибки записывается в лог-файл logs/llm_YYYYMMDD_HHMMSS.log
  • Обработка продолжается для остальных строк
Формат вывода:
  • Прогресс генерации в реальном времени
  • Статистика: обработано / пропущено / ошибок
  • Обновленный Excel файл с сгенерированным контентом
  • Детальный лог всех операций
Совместимость:

Команда работает с любыми OpenAI-compatible API, включая:

  • OpenAI GPT (gpt-4, gpt-3.5-turbo)
  • Anthropic Claude (через прокси)
  • X.AI Grok
  • Локальные LLM (через LM Studio, Ollama и т.д.)
  • Любые другие совместимые API
Режимы записи в файл
Автоматическое определение режима:

Команда llm автоматически определяет режим работы по имени колонки --column:

Колонка Режим Результат
content_path Генерация текста в файл Файл content/{id}.html, путь в Excel
img_path Генерация изображения Файл media/{id}.png, путь в Excel
Любая другая Обычный режим Текст записывается прямо в колонку
content_path — генерация текста в файл

Когда --column content_path, LLM генерирует текст, сохраняет в файл, а в Excel записывается относительный путь к файлу.

  • Файл сохраняется как content/{id}.html (ID записи из колонки id)
  • Постобработка (--md-to-html, --strip-tags, --html-to-md) применяется к тексту перед сохранением
  • С проектом: projects/<name>/content/{id}.html
  • Без проекта: data/content/{id}.html
# Генерация контента в файлы
wp-bulk llm --column content_path --file data.xlsx \
  --prompt "Напиши подробную статью про [title]" --md-to-html

# С проектом — файлы в projects/mysite/content/
wp-bulk -P mysite llm --column content_path --file data.xlsx \
  --prompt "Напиши описание [title]" --md-to-html

Результат в Excel: content/123.html, content/456.html, ...

img_path — генерация изображений

Когда --column img_path, LLM генерирует изображение, сохраняет в файл, а в Excel записывается путь.

  • Используются модели для генерации изображений (например, gemini-3-pro-image-preview)
  • Формат ответа API: choices[0].message.images[0].image_url.url (data:image/png;base64,...)
  • Файл сохраняется как media/{id}.png
  • С проектом: projects/<name>/media/{id}.png
  • Без проекта: data/media/{id}.png
# Генерация изображений
wp-bulk llm --column img_path --file data.xlsx \
  --model "gemini-3-pro-image-preview" \
  --prompt "A photorealistic image of [title], aspect ratio 1.91:1, professional lighting, no text"

# С проектом
wp-bulk -P mysite llm --column img_path --file data.xlsx \
  --model "gemini-3-pro-image-preview" \
  --prompt "Photorealistic [title], 16:9 aspect ratio, ultra detailed"

Результат в Excel: media/123.png, media/456.png, ...

Важно для img_path:
  • Используйте модели для генерации изображений через --model (не текстовые модели)
  • Таймаут для генерации изображений увеличен до 300 секунд
  • Промпт на английском языке дает лучшие результаты
  • Указывайте aspect ratio в промпте для контроля пропорций

image-crop

Обрезка изображений под размер или соотношение сторон

Назначение: Массовая обрезка изображений из папки проекта media/ (или указанной директории). Поддерживает обрезку по точным размерам, по соотношению сторон, и пять стратегий позиционирования. Автоматически исправляет ориентацию фотографий с телефона (EXIF). Опционально: градиентный overlay (затемнение снизу) и водяной знак (текст или картинка).
Параметры:
--input / -i папка с изображениями (по умолчанию: media/ проекта) --output / -o папка для результатов (по умолчанию: media/cropped/) --width / -W ширина в пикселях --height / -H высота в пикселях --aspect-ratio / -a соотношение сторон (16:9, 4:3, 1:1) --strategy / -s стратегия обрезки: center, top, bottom, left, right (по умолчанию: center) --gradient затемняющий градиент снизу, opacity 0.0-1.0 (по умолчанию: 0 — выключен) --gradient-height высота градиента, доля 0.0-1.0 (по умолчанию: 0.5) --watermark-text / --wt текст водяного знака --watermark-image / --wi картинка водяного знака (путь к файлу) --watermark-position / --wp позиция: center, bottom-right, bottom-left, top-right, top-left, bottom-center (по умолчанию: bottom-right) --watermark-opacity / --wo прозрачность водяного знака, 0.0-1.0 (по умолчанию: 0.3) --watermark-size / --ws размер шрифта текстового водяного знака (авто ~4% ширины) --watermark-color / --wc цвет текста #RRGGBB (по умолчанию: #FFFFFF) --watermark-scale масштаб картинки-водяного знака, доля от ширины (по умолчанию: 0.2) --glob / -g паттерн файлов (по умолчанию: *.{jpg,jpeg,png,webp}) --recursive / -r искать в подпапках --overwrite перезаписать существующие файлы --dry-run / -d показать что будет сделано без обработки --verbose / -v подробный вывод
Требования: Необходимо указать --aspect-ratio или оба параметра --width и --height. При указании aspect-ratio без размеров — обрезает до нужного соотношения, сохраняя максимальную площадь. При указании aspect-ratio + width — высота вычисляется автоматически.
Примеры использования:
wp-bulk image-crop -P ost --aspect-ratio 16:9
Обрезать все изображения проекта под 16:9 (максимальная площадь)
wp-bulk image-crop --input ./photos --width 800 --height 600
Обрезать до точного размера 800x600
wp-bulk image-crop -P ost -a 1:1 --strategy top
Квадратная обрезка с привязкой к верху (для портретов)
wp-bulk image-crop -P ost -a 16:9 --dry-run
Показать какие файлы будут обработаны (без изменений)
wp-bulk image-crop -P ost -a 9:16 --strategy left
Обрезка от левого края (стратегия left)
wp-bulk image-crop -P ost -a 16:9 --gradient 0.5
Обрезка + затемняющий градиент снизу (50% opacity)
wp-bulk image-crop -P ost -a 16:9 --wt "© MySite" --wp bottom-right
Обрезка + текстовый водяной знак в правом нижнем углу
wp-bulk image-crop -P ost -a 16:9 --gradient 0.4 --wt "© MySite" --wp center --wo 0.5
Обрезка + градиент + водяной знак по центру
wp-bulk image-crop -P ost -a 16:9 --wi logo.png --wp bottom-right --watermark-scale 0.15
Обрезка + картинка-водяной знак (логотип)
Формат вывода:
  • Rich прогресс-бар с процентом и ETA
  • Итоговая таблица: всего, обработано, пропущено, ошибки
  • Размер входных/выходных файлов и процент экономии
  • Результаты сохраняются в media/cropped/

image-compress

Сжатие изображений для веба

Назначение: Массовое сжатие изображений с контролем качества и максимальных размеров. Автоматически подбирает оптимальные параметры для каждого формата (JPEG, PNG, WebP). Поддерживает пропорциональное уменьшение через --max-width / --max-height.
Параметры:
--input / -i папка с изображениями (по умолчанию: media/ проекта) --output / -o папка для результатов (по умолчанию: media/compressed/) --quality / -q качество JPEG/WebP, 1-100 (по умолчанию: 80) --max-width максимальная ширина (пропорциональное уменьшение) --max-height максимальная высота (пропорциональное уменьшение) --strip-metadata / --keep-metadata удалить EXIF (по умолчанию: удалять) --glob / -g паттерн файлов (по умолчанию: *.{jpg,jpeg,png,webp}) --recursive / -r искать в подпапках --overwrite перезаписать существующие файлы --dry-run / -d показать что будет сделано без обработки --verbose / -v подробный вывод
Примеры использования:
wp-bulk image-compress -P ost --quality 80
Сжать все изображения проекта с качеством 80%
wp-bulk image-compress --input ./photos -q 75 --max-width 1920
Сжать до 75% качества и уменьшить до 1920px по ширине
wp-bulk image-compress -P ost -q 60 --max-width 1200 --max-height 800
Агрессивное сжатие с ограничением по обоим измерениям
wp-bulk image-compress -P ost --keep-metadata --quality 90
Лёгкое сжатие с сохранением EXIF метаданных
Особенности форматов:
  • JPEG: RGBA изображения автоматически конвертируются в RGB (белый фон)
  • PNG: используется optimize=True, параметр quality не применяется
  • WebP: полная поддержка quality + optimize
Формат вывода:
  • Rich прогресс-бар с процентом и ETA
  • Итоговая таблица: всего, обработано, пропущено, ошибки
  • Размер входных/выходных файлов, сэкономлено MB и %
  • Результаты сохраняются в media/compressed/

image-convert

Конвертация изображений в другой формат (по умолчанию WebP)

Назначение: Массовая конвертация изображений между форматами. По умолчанию конвертирует в WebP — современный формат с лучшим сжатием для веба. Автоматически обрабатывает прозрачность (RGBA → RGB с белым фоном для JPEG).
Параметры:
--input / -i папка с изображениями (по умолчанию: media/ проекта) --output / -o папка для результатов (по умолчанию: media/webp/) --format / -f целевой формат: webp, jpg, png (по умолчанию: webp) --quality / -q качество для lossy форматов, 1-100 (по умолчанию: 85) --strip-metadata / --keep-metadata удалить EXIF (по умолчанию: удалять) --glob / -g паттерн файлов (по умолчанию: *.{jpg,jpeg,png,gif,bmp,tiff}) --recursive / -r искать в подпапках --overwrite перезаписать существующие файлы --dry-run / -d показать что будет сделано без обработки --verbose / -v подробный вывод
Примеры использования:
wp-bulk image-convert -P ost --format webp
Конвертировать все изображения проекта в WebP
wp-bulk image-convert --input ./photos -f webp -q 85
Конвертировать фотографии в WebP с качеством 85%
wp-bulk image-convert -P ost -f jpg -q 90 --glob "*.png"
Конвертировать только PNG файлы в JPEG
wp-bulk image-convert -P ost --format webp --dry-run
Показать какие файлы будут конвертированы (входное имя → выходное)
Поддерживаемые форматы:
Целевой формат Расширение Особенности
webp .webp Лучшее сжатие, поддержка прозрачности, рекомендуется для веба
jpg .jpg Широкая совместимость, RGBA автоконвертация в RGB
png .png Без потерь, поддержка прозрачности, больший размер файла
Формат вывода:
  • Rich прогресс-бар с процентом и ETA
  • В dry-run показывает маппинг: photo.jpg → photo.webp
  • Итоговая таблица: всего, обработано, пропущено, ошибки
  • Размер входных/выходных файлов и процент экономии
  • Результаты сохраняются в media/<format>/
Обработка ошибок:
  • Повреждённые/нечитаемые файлы пропускаются с записью в лог
  • Существующие файлы (без --overwrite) пропускаются молча
  • Пустая папка / нет совпадений по паттерну — предупреждение и выход
  • Несуществующая папка — ошибка с exit code 1
